# nextcloud 0.10.0

Released 2026-10-26.

## Changes

### Office documents MCP server for agents

The chart installs the `mcp-officeagent` chart 0.1.1 (OfficeAgent.NET 1.2.0) in the same
project, on by default. Agents create, read and edit Word, PowerPoint and Excel files
through it; with a Nextcloud MCP server they read a file from Nextcloud, edit it in
`officeagent` and write it back, and Nextcloud keeps the previous content as a version.
The server edits files itself and does not use the OnlyOffice document server.

Its Service carries the agentgateway discovery keys, so an MCP gateway that selects
Services by them publishes it as `officeagent`. `mcp-officeagent.service.labels` sets a
gateway's exposure label and `mcp-officeagent.networkPolicy.ingressNamespaces` admits the
gateway's namespace; both are empty by default.

### OnlyOffice Document Server 10.0

The document server runs `onlyoffice/documentserver` 10.0.0.1 (was 8.2), pinned by digest.
Community Edition 9.4 and later have no limit of 20 simultaneous connections. The ONLYOFFICE
app in Nextcloud (10.2.1) connects to it unchanged.

### Agents edit documents live, next to people

The chart installs the `mcp-onlyoffice-live` chart 0.1.0 in the same project, on by default.
An agent opens a document in OnlyOffice as itself and joins the co-editing session: people
who have the document open see the agent's name, cursor and edits as they happen. The
document server serves the plugin `agent-bridge` from a ConfigMap
(`onlyoffice.agentBridge.enabled`), through which the server edits; in a person's editor
the plugin is invisible and idle. The server calls Nextcloud on the Service `nextcloud`
with the caller's own credential and opens editor pages on the public address from the
ConfigMap `nextcloud-public-url`.

Its Service carries the agentgateway discovery keys, so an MCP gateway publishes it as
`office-live`. `mcp-onlyoffice-live.service.labels` and
`mcp-onlyoffice-live.networkPolicy.ingressNamespaces` work as for `mcp-officeagent`.

### Open files are locked

The setup script enables the Nextcloud app `files_lock` (`onlyoffice.lockFiles`). The
ONLYOFFICE app then locks a file while it is open in the editor, and a WebDAV write to it,
by a person, a sync client or an agent, fails with `423 Locked` instead of being lost at
the editor's next save.

### Documents survive deleting the Application

The server's claim `officeagent-documents` (1Gi) carries
`argocd.argoproj.io/sync-options: Delete=false,Prune=false`, as the Nextcloud and mail
volumes do.

## Upgrade

- The document server restarts on the new image. Documents open in the editor at that
  moment reload; edits not yet saved by the editor are lost, so upgrade outside office
  hours or ask people to close their documents first.
- The upgrade adds a Deployment, a Service, a NetworkPolicy and a 1Gi
  PersistentVolumeClaim named `officeagent*`, and a Deployment, a Service and a
  NetworkPolicy named `office-live`, to the project. Set `mcp-officeagent.enabled=false`
  or `mcp-onlyoffice-live.enabled=false` to leave them out.
- The `office-live` server needs 512Mi and up to 3Gi of memory.
- The setup script enables `files_lock` at the next start of Nextcloud; the upgrade does
  not restart Nextcloud. Restart it in a quiet moment to lock open files from then on:
  `oc rollout restart deployment/nextcloud`.
