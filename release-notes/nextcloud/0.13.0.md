# nextcloud 0.13.0

Released 2026-10-27.

## Changes

### Three MCP servers on the Nextcloud host

The chart now also runs the Nextcloud MCP server (`mcp-nextcloud` 0.1.0) and
publishes each MCP server on the host of Nextcloud, with the host's
certificate: `/mcp/nextcloud`, `/mcp/officeagent` and `/mcp/office-live`.
`mcp.route.labels` and `mcp.route.annotations` add your own keys to these
Routes, `mcp.route.enabled: false` leaves them out. The NetworkPolicies of the
three servers admit the router.

### The officeagent checks tokens with oauth2-proxy and admits the tenant's administrators

`mcp-officeagent` moves to 0.3.0: the token check is oauth2-proxy (release notes
of `mcp-officeagent` 0.3.0). It now also requires the group
`<tenant>-admins`, where the tenant is the part of the project name before the
first `-` (`mcp-officeagent.auth.allowedGroups`).

### The MCP servers are packaged with the chart

`mcp-officeagent`, `mcp-onlyoffice-live` and the new `mcp-nextcloud` come from
the same commit of the chart repository instead of its index, so a release
never waits for another chart's release.

## Upgrade

The officeagent pod restarts with the new sidecar. Set
`mcp-officeagent.auth.resourceUrl` to `https://<host>/mcp/officeagent`. Under a
GitOps tool that renders without cluster access, pass
`mcp-officeagent.auth.cookieSecret` and `mcp-officeagent.auth.clientSecret`.
Callers of the officeagent that are not in `<tenant>-admins` now get 403: list
their group in `mcp-officeagent.auth.allowedGroups`. A Nextcloud MCP server you
run yourself in the project can go once agents use `/mcp/nextcloud`; set
`mcp-nextcloud.enabled: false` to keep yours instead.
