# nextcloud 0.16.0

## Changes

### Webmail without a second login

With OpenID Connect set up (`oidc.discoveryUri`, `oidc.clientId`), `secrets.type`
`kubernetes` and `mailRoute.sso.enabled` (default `true`), the menu entry Webmail opens
`https://<host>/mail/login`. An oauth2-proxy (Deployment `nextcloud-mail-login`) signs the
user in at the provider, with the instance's own client, and opens the Mailu webmail as the
mailbox of the user's email. The mailbox must exist; Mailu creates none.

Mailu takes the login only from its front end (`127.0.0.1/32`) and under a header name
derived from `secrets.mailLoginSecret`, both in Secret `nextcloud-mail-login`. Without that
Secret Mailu takes no login header, as before. Pass `secrets.mailLoginSecret` when the chart
is rendered without cluster access (Argo CD): a generated value changes on every render.

Without OpenID Connect nothing changes: the webmail asks for the mailbox password.

## Upgrade

- Add the redirect URI `https://<host>/mail/login/oauth2/callback` to the provider's client
  before the upgrade.
- An existing Webmail entry that still points at `https://<host>/mail/inbox/` is changed to
  the login and opens as a page instead of in a frame, since the provider's login page
  refuses a frame. Other entries stay.
- Mailu admin and Nextcloud restart once (pod environment, pod annotation `chart-version`).
