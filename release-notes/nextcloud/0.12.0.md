# nextcloud 0.12.0

Released 2026-10-27.

## Changes

### Nextcloud waits out a storage stall before a restart

On network storage (CephFS) a metadata failover freezes file access for about
a minute. The liveness probe of Nextcloud (`/status.php`) restarted the
container after 5 failed checks, inside such a stall. It now allows 12 failed
checks at 10-second intervals, about two minutes. Readiness still takes the pod
out of service after 5 failed checks.

### The Nextcloud exporter is checked on its port

With `monitoring.enabled` the probes of `nextcloud-exporter` asked for `/`,
which redirects to `/metrics` and runs a full scrape of Nextcloud's server
information within one second. A slow Nextcloud restarted the exporter. The
probes now check that the exporter's port answers.

### The TURN server starts before its DNS name exists

With `talk.turn.public` and no `talk.turn.externalIP`, coturn waited for its
DNS name (`turn-<host>` or `talk.turn.host`) and did not listen until the name
resolved, so the pod never became ready and the Application stayed Degraded.
It now starts without a public address and restarts itself with the address
once the name resolves, as it already did when the address changed. Calls
inside the cluster's network work in the meantime.

### Mail server: mailu 0.2.0

The mail server chart moves from 0.1.5 to 0.2.0 (release notes of `mailu`
0.1.6, 0.1.7 and 0.2.0):

- postfix and rspamd survive a storage stall: longer probe timeouts, and
  postfix starts again after it was killed with a lock left on `master.pid`;
- with `mailu.dns.enabled` the MX record of the mail domain is requested with
  SPF and DMARC (`mailu.dns.mx.enabled`, default `true`);
- `mailu.egressService` gets its own address and name (`outbound.<domain>`),
  named in SPF;
- `mailu.monitoring.alerts` leaves the alert rules out of `monitoring`;
- the imapsync image is pinned to 2.326.

## Upgrade

The Nextcloud, postfix and rspamd pods restart once, and with `monitoring`
and Talk enabled also `nextcloud-exporter` and `nextcloud-turn`. Files and mail
stay on their volumes.

A release with `mailu.dns.enabled` gets its MX record. If you made one by hand
at a DNS provider that external-dns serves, check with `dig MX <mail domain>`
that one record remains, or set `mailu.dns.mx.enabled: false`.
