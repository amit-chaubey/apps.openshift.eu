# guacamole 0.2.0

Released 2026-10-26.

## Changes

### Recordings reach a bucket behind the cluster's own certificate authority

The copy to the bucket now trusts the certificates in the ConfigMap
recording.s3.caConfigMap (default openshift-service-ca.crt) next to the system
ones. Before, a bucket endpoint signed by the cluster, such as the in-cluster
object gateway, refused every copy with "x509: certificate signed by unknown
authority", and the recordings stayed on the volume only.

### Recordings of a new database no longer replace older ones in the bucket

A recording is now named after its start time, `<YYYYMMDD>-<HHMMSS>`, inside
its history directory. The history directory name repeats when the database
is recreated, and the copy to the bucket replaced the older recording of the
same name. Recordings made before the upgrade keep the name `recording` and
still play back.

## Upgrade

Check the bucket before the upgrade if the database was ever recreated while
recording.s3.enabled was on: an object `<uuid>/recording` that is older than
the database belongs to the earlier database, and the first copy after the
upgrade replaces it with the recording of the same history number. Move those
objects to a prefix of their own first.
