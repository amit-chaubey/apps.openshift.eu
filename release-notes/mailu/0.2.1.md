# mailu 0.2.1

Released 2026-10-27.

## Changes

### Postfix keeps its PID file in memory

Postfix writes `master.pid` and takes its lock in `/queue/pid`. That directory is now a
per-pod memory volume instead of part of the queue volume, as upstream Mailu does since
Mailu/Mailu#4161. A lock on network storage (CephFS, NFS) can no longer outlive a killed
Postfix and block the next start. The queue itself stays on the persistent volume.

The init container that patched the Postfix start script as root is removed.

### Redis starts when the renderer does not detect OpenShift

The Redis container no longer carries an empty `seLinuxOptions`. A renderer that does
not report the OpenShift APIs, such as `helm template`, left it in, and admission then
refused the Redis pod, so the admin interface could not start.

### The admin interface waits for Redis at the first start

The admin interface creates its database and the first admin account at start, and that
step fails while Redis does not answer yet. It now waits for Redis before it starts. A
first install no longer ends with an empty database (`no such table: domain` in the log
of `mailu-admin`) when Redis starts later than the admin interface.

### Clients inside the cluster may log in without TLS

The front end accepts a password login without TLS from the networks in
`upstream.subnet`, as it already relays their mail and as Mailu's own containers talk to
each other. A mail client in the project, such as the Mail app of Nextcloud on the
webmail ports 10143 and 10025, needs no certificate it can verify. Clients from outside
keep their own address on the mail Service and still need TLS.

## Upgrade

No values change. Postfix restarts once, Redis only where its pod carried the empty field.
Restart the front end once to load the new login rule:

    oc rollout restart deployment/mailu-front
