# opencode-agent 0.3.5

Released 2026-10-22.

## Changes

### openhands 0.1.2 (Agent Canvas 1.30.0), owner or group login lockdown ([#34](https://github.com/hoolia/apps.openshift.eu/pull/34))

Agent Canvas 1.30.0 binds the frontend through STATIC_SERVER_BIND_HOST
instead of a literal --host ::, so the loopback patch rewrites both
assignments (the build still asserts two hits). The volume claim template
drops the version label: Kubernetes refuses any change there, so every
appVersion bump failed the StatefulSet update. A cookie secret that is
not 16, 24 or 32 characters long is hashed to 32, as in opencode-agent
and openwebui, so a 48-character generated value works.

opencode-agent 0.3.5 and openwebui 0.2.1: with neither oauth.ownerEmail
nor person.email set, the login proxy drops the emails file and admits
everyone who may get services/proxy on the UI Service, which admin and
edit grant. A team instance from a managed Template needs no e-mail.
Open WebUI then allows sign-up with role user; the first user is admin.
With an owner set the render is unchanged.

Every chart now offers two lockdowns. oauth.ownerEmail admits that one
user (emails file). oauth.allowedGroups admits only members of those
groups: the login Role grants the verb login on services/proxy of the
UI Service and the login proxy checks that verb. The previous check,
get on services/proxy, is also held by admin and edit, so any project
editor passed a group lockdown. With neither set, project editors log
in. openhands gains oauth.ownerEmail.

Verified on berry-ai with the authorization.openshift.io SAR the proxy
sends: a grncloud-engineering member is allowed login, a grncloud-admins
project admin and an outsider are refused, the same admin is allowed get.

The group lockdown checks the verb login, which only the login Role grants; the tests asserted the previous verb get.
