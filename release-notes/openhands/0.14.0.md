# openhands 0.14.0

Released 2026-10-28.

## Changes

### Repositories on the volume are selectable in a new conversation

The agent server runs in the pod, so the UI is a local backend. Its workspace picker
lists directories on the volume; the GitHub and GitLab repository list is a feature of
the upstream cloud backend only, which is why the picker offered no repository. On
every start the chart now registers `~/repositories` (new value `git.repositoriesDir`)
as a workspace parent: every repository in it is listed in the picker, then **Local**
works in the checkout and **Worktree** on a new branch in a worktree of it. The new
value `git.repositories` lists https URLs that are cloned into it at start when not
there yet; a repository cloned into it from the agent's terminal is listed right away.

### git uses provider tokens from the secrets store

The new value `git.providers` names further git hosts, `{type, host, secretName}` with
`type` `github` or `gitlab`, for example a self-hosted GitLab. git asks the agent-server
secrets store for the token `secretName` when it clones, fetches or pushes over https
to that host, before the `git.host` token. `secretName` defaults to `GITHUB_TOKEN`, then
`GITHUB_PERSONAL_ACCESS_TOKEN`, the name the GitHub card of the MCP library saves, and to
`GITLAB_TOKEN`, the name of the GitLab card, so a token saved for the MCP server also
serves git. The token stays out of the pod spec, command lines and logs.

### The image is rebuilt as `1.34.0-0.14.0`

The image content is unchanged; every chart release builds its own image tag.

## Upgrade

Nothing to do. To pick a repository, add it to `git.repositories` or clone it into
`~/repositories`. For a host other than `git.host`, store its token in
**Settings > Secrets** and add it to `git.providers`. The first sync builds the image
`1.34.0-0.14.0` and the pod restarts once on it.
