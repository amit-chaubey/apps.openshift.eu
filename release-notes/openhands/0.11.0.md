# openhands 0.11.0

Released 2026-10-27.

## Changes

### The agent's own token reaches MCP servers of its issuer

An MCP server that takes OpenID Connect tokens of the agent's own issuer (the
realm of `tokenProxy.agentToken.tokenUrl`) now gets the agent's token, on any
host: a RemoteMCPServer annotated `mcp.openshift.eu/auth: oidc` with
`mcp.openshift.eu/oidc-issuer` equal to that issuer, or a server whose
protected resource metadata (RFC 9728) names that issuer for its own URL. The
MCP sync fetches the metadata without a credential and caches it for an hour.
The token proxy forwards only to the URLs the MCP sync registered, over https
with the system trust store or to a cluster Service; any other address gets
403. A RemoteMCPServer of another issuer is skipped with the reason in the log.
Servers that log in users with OAuth (`openhands.dev/auth: oauth2`) are
unchanged.

### RoleBinding renamed

The RoleBinding that lets the MCP sync read RemoteMCPServers is now
`mcp-discovery-<name>` instead of `<name>-mcp-discovery`.

## Upgrade

The agent pod restarts once. Nothing else to do; the new routing needs
`gateway.upstream` and `tokenProxy.agentToken.tokenUrl`, as the agent token
already did.
