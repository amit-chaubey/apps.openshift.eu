# openhands 0.23.0

Released 2026-11-17.

## Changes

### Profiles get the input limit of their model from the gateway

A profile without `max_input_tokens` had no context window in OpenHands: the conversation
panel showed no real context use, and the condenser only counted events. A conversation on a
model with a 1M-token window was summarized after 120 events, at about 200k tokens.

The seed script now reads the context window of each model from the gateway's `/v1/models`
list and sets `max_input_tokens` of the profile with the same model name (after the last
`/`) to a share of it: `llm.contextShare`, 0.6 by default, rounded down to thousands. A 1M
window gives 600000, a 262144 window 157000. OpenHands counts the history and every MCP tool
definition against it, also the tools the gateway defers, and the condenser summarizes the
history above it; the rest of the window is left for the reply.

A result below `llm.minInputTokens`, 150000 by default, is not set: the tool definitions
alone can fill such a limit, and the condenser would then run on every step. Those models
condense on `condenser.maxSize` only, as before.

`llm.profileDefaults` and `llm.modelProfileDefaults` still win. The limits are written once
per value, like the other profile defaults: an edit under **Settings > LLM** stays until the
gateway reports another window.

### The condenser keeps 240 events

`condenser.maxSize` is 240 by default instead of 120, the OpenHands default. A model with a
limit from the gateway usually condenses on tokens first.

## Upgrade

Every gateway model profile with a window of at least 250000 tokens gets `max_input_tokens`
at the next pod start. Set `llm.contextShare: 0` to keep the profiles as they are, or
`condenser.maxSize: 120` for the old event limit. Conversations that exist keep the settings
they started with. The agent image is rebuilt once under the tag `1.38.0-0.23.0` and the
agent pod restarts.
