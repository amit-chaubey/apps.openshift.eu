# openhands 0.1.0

Released 2026-10-22.

## Changes

### Add openhands 0.1.0 chart ([#30](https://github.com/hoolia/apps.openshift.eu/pull/30))

Shared OpenHands Agent Canvas behind an OpenShift login. One StatefulSet
runs agent-canvas, oauth-proxy and a token proxy that sends the pod's
ServiceAccount token to an OpenAI-compatible gateway for models and MCP.

The upstream chart cannot carry sidecars and pins UID 10001, which
restricted-v2 rejects. This chart builds the upstream image with an
OpenShift toolset, runs it with an arbitrary UID, keeps the session key
out of the page, seeds model and MCP settings through the agent-server
API once per value change, and admits only groups that hold create on
services/proxy (cluster-reader holds get).

Verified live on berry-ai as release sam-10x: restricted-v2, login
redirect, completion through the gateway, MCP tools listed, restart
keeps conversations and settings.

build.toolsImage copies every binary of an image such as opencode-agent
(its /usr/local/bin except OpenCode, Go toolchain, /tools, sonar-scanner
and Ansible collections), so both agents carry the same CLI versions.
Python and npm tools are tied to that image's Alpine runtimes and are
reinstalled on Debian at pinned versions from build.tools; the build
runs one check per tool as a non-root UID and fails on any miss.

kubernetesMcpServer adds the local stdio MCP server the opencode agents
use. The agent-server starts stdio servers with a reduced environment,
so the seed hook hands KUBERNETES_SERVICE_HOST and _PORT through
passEnv. mcpServers entries take enabled, because the agent-server lists
all servers within one 30 s budget and one slow server drops them all.

The login check is back to get on services/proxy: cluster-reader does
not hold it; the earlier switch to create rested on a malformed test.

Verified live on berry-ai as sam-10x: every tool check passes, kubernetes
and public MCP tools work in a UI conversation, PDF upload and parsing
work in the UI.

A new browser met "No backend configured" and had to paste the session
API key: the upstream entrypoint binds the frontend to ::, and then it
does not embed the key. The image now rewrites that flag to 127.0.0.1
(the build fails when the upstream text is not found). On loopback the
frontend embeds the key, so a logged-in browser gets a connected
backend, and only oauth-proxy in the pod can fetch that page.

The agent-server also listens on 127.0.0.1, so the probes run curl in
the container. Verified on berry-ai: neighbour pod sees 8000 and 18000
refused; fresh browser opens without a backend prompt and chats.
