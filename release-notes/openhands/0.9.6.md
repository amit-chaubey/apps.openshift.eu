# openhands 0.9.6

Released 2026-10-26.

## Changes

### Google Workspace, Microsoft 365 and Azure CLIs in the image

The image the chart builds now carries `gws` (Google Workspace CLI 0.22.5),
`m365` (CLI for Microsoft 365 11.11.0) and `az` (Azure CLI 2.91.0), next to
`aws` (AWS CLI v2, a Debian package) that it already had. They are entries of
`build.tools` at pinned releases, and the build runs each of them once and fails
when one does not start.

`build.tools` takes two new kinds for them: `venv` installs a requirement with
pip into its own environment under `/opt/venv`, and `tarball` installs a
binary from a release archive after checking the archive against its SHA-256
digest.

The image holds no credential for these CLIs. Log in from the agent's terminal:
`gws auth login`, `m365 setup` once and then `m365 login`, `aws configure sso`,
`az login --use-device-code`. The login is kept in the container, outside the
data volume: after a pod restart, log in again.

The image grows by about 700 MB, mostly the Azure CLI and the CLI for
Microsoft 365.

## Upgrade

Nothing to do. If you set `build.tools` yourself, add the three entries from
the chart's `values.yaml` to get the new CLIs. The upgrade starts a new image
build, and the pod restarts on the new image when it is done.
