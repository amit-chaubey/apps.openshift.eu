# openhands 0.10.0

Released 2026-10-26.

## Changes

### The whole home directory persists

`/home/openhands` now lives on the data volume (subdirectory `home`), so CLI
logins, MCP OAuth tokens, tool configuration in `~/.config` and `~/.local` and
caches survive a restart. `~/.openhands` and `~/workspace` stay in their own
subdirectories, mounted inside the home, so existing settings, conversations
and work trees need no migration. `~/.claude` is now part of the home
subdirectory instead of a subdirectory `claude` of its own. A new init
container, `seed-home`, copies the files the image ships in its home
(`.bashrc`, `.profile`, `.bash_logout`) into the volume when they are missing
and never overwrites one. Caches such as `~/.cache/uv` grow on the volume.

### MCP servers that each user logs in to with OAuth

A RemoteMCPServer annotated `openhands.dev/auth: oauth2` becomes an MCP server
that each user authorizes in the browser, for example a vendor's hosted MCP
server for mail or calendars. The entry uses the server's own URL and the
pre-registered OAuth client in the Secret named by `openhands.dev/oauth-client`
(keys `client_id` and `client_secret`), with the scopes of
`openhands.dev/oauth-scopes`. Without `openhands.dev/oauth-client` the agent
registers itself at the server (dynamic client registration). It appears switched off under Settings > MCP: open
it, authorize it, switch it on. The agent keeps the tokens encrypted in its
settings and refreshes them; a later change of the client id, the scopes or the
Secret is written to the entry without logging the user out.

### Add-on MCP servers by bundle or name

A RemoteMCPServer labelled `mcp.openshift.eu/addon: "true"` reaches the agent
only when its `mcp.openshift.eu/bundle` is in `mcp.bundles` or its
`mcp.openshift.eu/server` is in `mcp.servers`, for example
`mcp.bundles: [google-workspace]`. The `mcp-*` charts of this repository stamp
these labels. Servers without the add-on label are discovered as before.
`mcp.labelDomain` changes the prefix.

### Google issues a refresh token

An authorization request to `accounts.google.com` asks for offline access, so a
Google login keeps working after the first hour. This needs `build.enabled`.

### mcpDiscovery is now mcp

The values under `mcpDiscovery` moved to `mcp`. `mcpDiscovery` is still read in
this version and its keys override `mcp`.

## Upgrade

Move any values under `mcpDiscovery` to `mcp`; the next minor version stops
reading `mcpDiscovery`. List the add-on bundles or servers an agent should get
in `mcp.bundles` or `mcp.servers`. The upgrade rebuilds the image and restarts the
pod once. What the tools kept in the home outside `~/.openhands` and
`~/workspace` before the upgrade (CLI logins, `~/.config`, caches) was not on the
volume and starts empty once; log in to the CLIs again.
