# odoo 0.1.3

Released 2026-10-13.

## Changes

### Write chart labels as literals ([#7](https://github.com/hoolia/apps.openshift.eu/pull/7))

Every chart built its labels through a helper that took a dict and
returned all five labels, so a reader had to open the helper to learn
what an object is called. app, app.kubernetes.io/name and
app.kubernetes.io/component are now literal lines on each object. One
helper per chart, <chart>.commonLabels, emits what is the same on
every object: part-of and version, or version alone in nextcloud,
which draws several groups and writes part-of on the object.

The nextcloud topology table is gone as well: the console keys
(runtime, vcs-uri, connects-to, custom-icon) are literal lines on the
workloads.

A value stays an expression where it must follow a name that is one:
the fullname in mkdocs, omniroute and mailu, the upstream name
override in mailu, and the loop and helper arguments in nextcloud.

No selector, pod template or value changes. The rendered objects are
the same as before.

The contributor rules still asked for one helper that emits all five
labels. They now state what the charts do: three literal labels on
each object, <chart>.commonLabels for part-of and version, console
keys and sync-wave numbers as literals in the template.

ci/check_labels.py reads the rendered objects, not the helper, so it
needs no change.

The templates of every chart changed, and a change to a chart raises
its version. The rendered objects are the same, so this is a patch.

nextcloud keeps bundling mailu 0.1.5: the dependency is resolved from
the published repository, and 0.1.6 renders the same objects.
