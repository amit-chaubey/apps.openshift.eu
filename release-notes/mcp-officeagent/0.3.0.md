# mcp-officeagent 0.3.0

Released 2026-10-27.

## Changes

### The token check is oauth2-proxy instead of Envoy

With `auth.enabled` the sidecar is now oauth2-proxy v7.15.5 from the shared
library chart `mcp-auth`, the same check as every other MCP server chart of
this repository. For a caller nothing changes: no token or a token of another
issuer or audience gets 401, a token of another group 403, `/healthz` passes
without a token. New: with `auth.issuerUrl` set,
`/.well-known/oauth-protected-resource` names the issuer as authorization
server (RFC 9728) without a token; `auth.resourceUrl` sets the address it names.
`auth.audiences` empty now means the release namespace instead of any audience,
because oauth2-proxy always checks the audience. An entry of
`auth.allowedGroups` is a template, as one of `auth.audiences` already was.

### The token check keeps two generated secrets

oauth2-proxy requires a cookie secret and a client secret, which bearer tokens
never use. The chart generates both once into the Secret `<name>-auth` and keeps
them on upgrade; `auth.cookieSecret` and `auth.clientSecret` set them,
`auth.existingSecret` names your own Secret.

## Upgrade

With `auth.enabled` the pod restarts with the new sidecar. Remove
`auth.jwksUri`, `auth.streamIdleTimeout`, `auth.caFile` and `auth.logLevel`
from your values: oauth2-proxy reads the signing keys from the issuer's
discovery document and has no idle limit on a stream, and the schema refuses the
old keys. Set `auth.audiences` if a token for any audience of the issuer was
accepted before. Under a GitOps tool that renders without cluster access, pass
`auth.cookieSecret` and `auth.clientSecret`. Without `auth.enabled` nothing
changes.
