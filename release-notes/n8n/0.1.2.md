# n8n 0.1.2

Released 2026-10-11.

## Changes

### Label every chart object

Every object a chart renders from its own templates now carries
app and the app.kubernetes.io labels name, component, part-of and
version, so the console and label queries can tell which
application and which component an object belongs to. Each chart
gets one small helper that emits them.

Workloads and the database and cache resources also get a runtime
icon, the upstream source address and, where a component depends
on another, a connects-to arrow for the topology view.

The labels sit on the object's own metadata only. Pod templates
and selectors are unchanged, so an upgrade restarts no pod. Three
charts hash a rendered file into a pod annotation (n8n, odoo,
vaultwarden): that hash is taken without the new labels and keeps
its value.

Objects of the upstream subcharts are labelled where the upstream
chart has a value that reaches object metadata only: the workload
of bifrost, the objects of mailu except its Redis subchart, and
the workload, volumes and imaginary Service of nextcloud.

All ten charts move up one patch version.
